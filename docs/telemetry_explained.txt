TELEMETRY.PY — RECORDING WHAT HAPPENS
======================================

Purpose
-------
telemetry.py records evidence about each agent execution. It does not predict
failure yet. It creates clean, consistent logs that will later become the ML
training dataset.

There are two levels of telemetry:

- A StepEvent records one action during a run.
- A RunEvent records the final summary of an entire run.


1. WHAT IS A RUN?
-----------------
One run is one attempt by the agent to answer one user task.

For example, asking "What is 25 * 17?" is one run. It may contain these steps:

    Step 1: call Llama
    Step 1: call calculate tool
    Step 2: call Llama again for the final answer

Every record from that attempt shares one unique run_id. This lets us group
all actions from the same task together later.


2. utc_now()
------------
utc_now returns the current time in UTC. UTC is used because it avoids
confusion between time zones when logs are compared across machines.


3. StepEvent
------------
StepEvent inherits from Pydantic's BaseModel. It defines the exact shape of a
single step record.

Important fields include:

- run_id: which full agent attempt this event belongs to.
- model: which Ollama model was used.
- task_type: rough category, such as calculation.
- step_number: position in the loop.
- event_type: either llm_call or tool_call.
- timestamp: when the event was written.
- latency_ms: how long the LLM call or tool execution took.
- tool_name: the requested tool, for tool events.
- tool_success and error_type: whether the tool worked.
- input_tokens and output_tokens: token counts reported by Ollama.

Pydantic validates these fields. For example, latency_ms cannot be negative,
step_number must be at least 1, and event_type can only be llm_call or
tool_call. This matters because unreliable logs create unreliable ML data.


4. RunEvent
-----------
RunEvent is one final summary record written after a task finishes. It has
values accumulated in runner.py:

- num_llm_calls
- num_tool_calls
- num_tool_errors
- num_retries (currently always zero; retries come in a later milestone)
- input_tokens and output_tokens
- total_latency_ms
- final_answer_generated
- failed and failure_type

Later, one RunEvent can become one row in a run-level ML dataset.


5. TelemetryCollector
---------------------
TelemetryCollector owns the destination folder and provides two simple
methods:

    record_step(event)
    record_run(event)

The constructor makes the folder if needed:

    self.directory.mkdir(parents=True, exist_ok=True)

It saves raw logs in:

    telemetry/steps.jsonl
    telemetry/runs.jsonl


6. WHAT IS JSONL?
----------------
JSONL means JSON Lines. Each line in the file is one complete JSON object.

Example line in steps.jsonl:

    {"run_id":"abc", "step_number":1, "event_type":"tool_call",
     "tool_name":"calculate", "tool_success":true, "latency_ms":0.06}

The next event is written on the next line. This is useful because the agent
can append new records without reading or rewriting old ones. pandas can load
it later with read_json(..., lines=True).


7. _append()
------------
_append is the low-level writing method. It:

1. uses Pydantic's model_dump(mode="json") to make JSON-safe values;
2. converts that data to JSON text with json.dumps(...);
3. adds a newline;
4. opens the file in append mode ("a") and writes it.

Append mode means new telemetry is added to the end; previous run records are
preserved.


8. elapsed_ms()
---------------
elapsed_ms takes a start time made with time.perf_counter() and returns the
elapsed duration in milliseconds. perf_counter is chosen because it is a
high-precision timer suitable for measuring performance.


9. WHY THIS HELPS THE FUTURE PREDICTOR
---------------------------------------
The raw events let us construct features available while a run is still in
progress, such as:

- number of tool errors so far;
- current total latency;
- number of tool calls;
- repeated calls;
- tokens used;
- current step number.

When failure injection is added, each completed RunEvent will also receive a
reliable failed label. The predictor can then learn whether patterns visible
at an earlier step are associated with eventual failure.


10. LIBRARIES USED HERE
-----------------------
pydantic: validates event data using BaseModel and Field.
json: Python built-in; converts records to JSON text.
time: Python built-in; measures elapsed time.
datetime: Python built-in; records UTC timestamps.
pathlib: Python built-in; handles file locations.
typing.Literal: Python built-in; restricts allowed field values.

There is no OpenTelemetry package yet. The structure borrows the useful idea
of run-level and step-level events while staying simple enough to learn from.
